# DOC 1 // Guarded reclaim custody proposal
Production reclaim HOLD. Source-only design, no deletion, privilege, new helper command or UI action.

Current withdrawal keeps the inactive file and records deliberately. Current recovery fence is inside the extension directory and returns when that directory is absent; using it for physical reclamation would lose the fence exactly when it is most needed. Reclaim requires a protected fixed sibling state location outside the extension subvolume (exact path/schema pending review) checked by every mutator, including inspection-lock reactivation/archive paths, before any side effect. A preexisting/partial/unreadable external marker must block even if the extension directory is absent. Do not deploy until all legacy entrypoints that ignore it are retired and a trusted installer/Connections transport is reviewed. Ordinary root tools remain outside the cooperative boundary.

Initial scope: only the already inactive managed temporary extension, never the base, zram, other disk or an arbitrary path. Exact verified withdrawal result via integrated helper classifier; both real base/extension identities, boot policy, no alias of active inode, same single-device Btrfs subvolume and expected contents, no nested/extra entries, no reactivation or archive pending. Current v1 withdrawal records contain no boot ID. Require a new contemporaneous protected boot/digest witness as part of future withdrawal, NOT a retrospective witness generated from current boot or user queue. Existing v1 records remain ineligible until an independently reviewed migration exists. Pure prototype's booleans are not evidence or authority; future executor must observe actual facts with protected custody under common lock, fresh explicit authorization and rechecks.

Required next implementation ordering: publish and fsync exact withdrawal archive outside the extension, including full records, file identities and boot witness; read back and re-fsync, publish external durable PREPARED fence outside extension, fsync file and parent, revalidate all evidence. Only then consider fixed-dirfd unlink of the exact inactive swapfile, then fixed journal retirement and nonrecursive deletion of exact empty subvolume using separately reviewed Btrfs semantics. No arbitrary paths, recursive delete, swapoff, reformat, blind cleanup or replay. Independently verify kernel base unchanged and extension absent, directory absent, archive retained, storage-accounting evidence; directory disappearance does not prove blocks immediately freed (snapshots/CoW). Publish separate durable result outside subvolume; explicit review/clear protocol separate from effect. Any interruption keeps external fence, preserve archive, unknown result; no auto-retry. Never overwrite prepared state or clear on absent directory. Versioned exact archive and intent/result schema and durable lifecycle need separate implementation/review. Pure fence classification is not live enforcement. Unit fixtures use exact integrated helper source, no filesystem effects. Native disposable tests for every publication, sync, unlink, subvolume deletion and result boundary, external interference and reboot remain required.
