## IMPLEMENTATION

`StationMediaSubjectPane` already mounts the original `StationRadio` for its three native MEDIA RADIO routes. These routes reuse the actual shared `HeadlessMediaController`, the original `weather-radio` client, MPD transport and existing `weather-radio-memory.json`; no new radio provider, playback server or persistence namespace is created.

M28-E extends M28-D's explicit `WIRED_IN_SUBJECTS` registry with exactly six original control families:

- RADIO directory, search presets, and paging → `media/radio/directory`.
- Favorites and recents → `media/radio/saved`.
- Select/load/enter and play/pause/stop → `media/radio/transport`.

The INDEX generated by M28-D now offers native SUBJECTS destinations for all six RADIO mappings, with three deduplicated route buttons. The historical M1 source map remains untouched; unreviewed WATCH, CREATORS, WEATHER, COSMOS and EARTH links remain available through CLASSIC. This does not remove the CLASSIC radio source component or claim full Weather Station parity.

## HOW TO USE

After merge and separate local deployment: Weather Station → SUBJECTS → INDEX → MEDIA → RADIO. Choose **OPEN SUBJECTS // MEDIA/RADIO/DIRECTORY**, **.../SAVED**, or **.../TRANSPORT**. Alternatively use SUBJECTS → MEDIA → RADIO and select the relevant subroute from its existing controls.

Directory includes source search/presets and pagination. Saved shows favorites and recents. Transport includes selection, loading and playback controls. Existing Hi-Fi/MPD availability still determines actual playback.
