## IMPLEMENTATION

Merged C3e-AG PR #2006 establishes real local Linux process observation (pidfd, UID/GID, script/executable SHA-256, cgroup, LSM and post-read replacement guards), but its caller supplies the expected script hash. Identity DOC's earlier `services/identity/silverblue_release_candidate_v1.py` independently validates a purpose/role-scoped Ed25519-signed C4b RPM release manifest and exact nine-file roster, but does not inspect a running process.

This **C3e-owned** addition composes the two existing unchanged functions in a single read-only operation:

1. Freeze caller-provided, independently pinned source file map and expected process snapshot before any verifier runs.
2. Require the expected process script SHA-256 to equal the signed release's `/usr/libexec/post-apollo/identity/identity-gateway-ci` manifest entry, without trusting a digest reported by the process itself. Require the exact installed script path and C4b unit in optional real guest mode.
3. Verify the existing Identity Ed25519-signed release envelope, separate root and receipt public-key pins, RPM SHA-256, exact nine-file SHA-256 roster and version floor via **unchanged** Identity release verifier.
4. Only after the signed source preflight, call unchanged C3e-AG to inspect the actual Linux process, interpreter inode/hash, root-owned script file bytes, /proc identities and native state.
5. Return only CI-qualified source/process continuity fields. All host, independent signer, external issuer, C5, credential, sign-in and production authority flags remain false.

The default GitHub CI starts an actual unprivileged Python interpreter executing a root-owned test gateway script, under an independently pinned disposable Ed25519 signed release fixture. The 22-case suite checks a valid source/process match and denies wrong release root, wrong signature, tampered manifest, altered roster/RPM/receipt pins, rollback, changed running script, wrong PID/executable, process exit, missing fields, and unauthorized guest mode. A mutation test confirms caller-owned maps cannot swap expected source or process hashes between source and kernel verification.

This is a **meaningful cross-layer join**, but the signed release key, actual RPM hash and reference files in this fixture remain disposable CI inputs. C4b's official Fedora 44 Silverblue running installed service has not been exercised by this C3e composition. It does not enroll the operator's production signing root.

## WATCH OUT FOR

**Signed source is not signed remote kernel evidence.** A matching local script SHA-256 proves only that the on-disk file currently matches expected source bytes. It cannot prove code loaded into Python memory, an immutable enrolled package deployment, a logind user seat, or a trusted native peer process. A local `/proc` observation can be forged when exported without a separately controlled, challenge-bound signer. Distinct CI keys in one runner are not independently protected operator keys.

**Process source pins are supplied by CI.** Even though the signed release is verified, these tests do not independently verify installation, RPM/OSTree identity, external rollback resistance or SELinux domain provenance. The root-local one-use issuer in C3e-Y/Z remains a separate CI experiment and is not involved here. One-use C5 human intent remains independent.

All authority flags remain false. Do not connect this to the production broker or enable sign-in based on these results.
