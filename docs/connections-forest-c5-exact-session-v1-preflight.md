## IMPLEMENTATION // Why this is a new version

The previously reviewed #2171 v0 COMMIT intent signs principal, Tree, user turn, persisted attempt ID, request, model, revision, lease, host/process evidence and consent epoch, but does **not** include the exact durable Forest sessionId. Forest's B4c #2208 persistence has session_id in its original immutable attempt context. It also uses an untrusted synthetic held permit and terminal callback. Forest owner [recommended option A](https://github.com/kudokudo1/The-Post-Apollo-Project/pull/2233#issuecomment-7094482721): a **distinct versioned signed session field**, not a mutation of v0.

This candidate adds a strict, canonical **v1 signed COMMIT_GENERATE fixture** with all v0 fields unchanged plus sessionId:
- Intent schema postapollo.forest.commit-intent.v1, same **Forest-only** audience postapollo.forest.conversation.v1, same phase COMMIT_GENERATE / action GENERATE, and EXACT sessionId.
- Separate role evidence schema postapollo.forest.signed-role-evidence.v1. Requester and consent-reviewer are distinct Ed25519 fixture roles over the SHA-256 digest of the complete canonical V1 intent, including sessionId. Neither uses an Identity/TimeW/Hospital issuer.
- Terminal receipt schema postapollo.forest.commit-terminal-receipt.v1; separate writer signature binds digest of complete V1 intent, exact sessionId, principal, Tree, user turn (through intent digest), attempt, request, grant, model, revision, consent, release, claimed permit, storage transaction label, journal predecessor and counter.
- A caller-provided **replica** of B4c's eight-field SyntheticCommitBinding is checked exactly against V1 intent, including session_id. This is **not** a trusted read of the real B3 database.
- Receipt inspection is allowed *after the original grant expiry* for crash-recovery diagnostics only, never to regain permission. Original lease must be structurally valid (positive times, bounded <=300,000 milliseconds).
- Strict exact fields, canonical JSON, duplicate-key and non-JSON rejection; exact types reject booleans as counters. Three independently distinct fixture public keys, separate Ed25519 signatures, original Forest-only role/audience checks and replay-counter/predecessor checks.
- **No v0 to v1 auto-migration, permissive decode, schema negotiation or fallback.** The current v0 modules, runtime consumer and existing signed record formats remain unchanged.

### All apparent trust is caller-supplied

Public keys, B4c binding, supposed journal predecessor, counter floor, writer release, role records, permit/transaction and terminal status are all generated by disposable CI, not a protected source. An attacker who fabricates all three keys and the putative B3 context can construct a fully matching signed record without committing anything.

A return of V1_SESSION_BOUND_FIXTURE_CONSISTENT_NOT_AUTHENTICATED means **ONLY that caller-controlled bytes agree**. It does **not** mean:
- enrolled signer keys or verified human consent
- original installed writer, process/seat/release, or protected original B3 database context
- an actual SQLite COMMIT/ROLLBACK and journal durability
- independent monotonic journal head/antirollback custody
- genuine one-operation protected C5 permit, current revocation/consent, or settlement
- safe READ_SESSION, model/tool execution, production activation, or revocation ACK

All authority flags stay **False**, safeActions remains **empty**, and no real program invokes this verification module. It cannot settle UNKNOWN_HOLD, which must remain through lost receipt/acknowledgment, crash, replay ambiguity or issuer outage. Do not treat a signed ROLLBACK claim as actual proof of absence of a committed Forest reply.
