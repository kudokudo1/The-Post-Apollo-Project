# Clock BG1-B2B12 // Protected Signed Session Enrollment

**State:** New production-path **read-only verifier** and deny-only native
supervisor integration, not an installed authorizer. The running QML
singleton remains the only live V2 alarm writer in hard-coded ACTIVE mode.
No installed issuer, signing key, production root-pin release or monotonic
floor has been provisioned or changed by this stage.

## Why it matters

B2B9 established independently pinned **installed program** identity.
B2B10 added a real Linux foreground AF_UNIX socket server, and B2B11
persisted a simulated signed test process session epoch. However,
production still had no way to determine that the connected process's
specific **session** had been independently approved: the PID/ticks in
the disposable test roster were generated by the harness, not a
protected supervisor signing authority.

B2B12 provides a concrete, purpose-separated signed session enrollment
file contract and reads it from a fixed protected installation path,
then rechecks the exact AF_UNIX kernel peer and B2B9 role identity.

## Protected enrollment contract

The proposed independently privileged Clock controller writes only
the following *signed* bytes into:

`/run/post-apollo/clock/sessions-v1/clock-ui-bridge-session-v1.json`

and a matching 64-byte Ed25519 signature:

`/run/post-apollo/clock/sessions-v1/clock-ui-bridge-session-v1.sig`

These paths are **not created by the new code**. Only root-controlled
directories with no group/world writable ancestors are accepted.
Manifest and signature must be regular root-owned files with no
additional hard links, group/world write permissions or symlinks;
bounded `O_NOFOLLOW` reads check inode and metadata consistency.
A separately installed Clock release-root public key remains pinned
by an **independently approved fingerprint**, not the requester's
socket payload or environment.

The exact canonical manifest has these named fields:

| Key | Role |
| --- | --- |
| schema, purpose | `postapollo.clock.bg1.installed-session.v1` and Clock-only enrollment purpose |
| role | Exactly `clock-ui-bridge` |
| bootId | Exact live Linux kernel boot UUID |
| pid, startTicks | Original installed old-writer process and kernel start ticks |
| uid, gid | Signed process credential pins |
| releaseEpoch, releaseSequence | Same installed B2B9 signed role release version |
| socketScope | Exactly `post-apollo-clock/clock-supervisor-v1.sock` |

The enrollment signature has its **own Clock domain prefix** distinct
from the program-role certificate and Identity Center/Connections.
Unknown fields, duplicate fields, noncanonical JSON, earlier boot,
different release, invalid UID/GID, wrong PID/ticks or wrong signer
refuse. The release-floor input must already come from protected,
monotonic supervisor custody; a signature alone is not anti-rollback.

### Runtime verification

A foreground native supervisor already listening at
`/run/user/<uid>/post-apollo-clock/clock-supervisor-v1.sock`
may invoke this verification **only if** it has separately provisioned,
reviewed values for:
- `APPROVED_CLOCK_RELEASE_ROOT_SHA256`
- `APPROVED_CLOCK_RELEASE_FLOOR`

Both are intentionally **None** in the current repository, and
**there is no environment variable, command-line flag or socket
request to set them**. Merely copying files into either protected
path does not activate native session admission.

If a future approved package provides the independent pins, the
supervisor reads the protected enrollment and installed B2B9
signed-role bundle, pins the *accepted socket's actual kernel peer*
with SO_PEERPIDFD, verifies executable inode/hash/argv, matches
boot/PID/ticks/UID/GID and release epoch/sequence, rechecks signed
files after inspection and verifies the process has not exited.

Even if all observations match, the only possible response is:
`ok=false`, `originObserved=true` and
`OBSERVED_ONLY_NOT_AUTHORIZED`.
Every authority field remains false:
`roleAuthenticated`, `writerStopped`, `releaseAcknowledged`,
`oldWriterRestartPrevented`, `ownsRealAlarmFile`,
`canTransferOwnership`, `canRing`, `canNotify`.

No code in this PR can enact `REQUEST_PAUSE`, `RELEASE_WRITER`,
`TAKE_OWNERSHIP` or `RING_ALARM`. Those remain refused even for
a correctly signed process.

## Verification

CI starts a real Linux AF_UNIX old-writer test child with kernel
pidfd evidence; an ephemeral test-only Ed25519 signing root signs
both installed role and specific session using different domains.
It exercises valid same-process observation; wrong signer/domain,
incorrect independent pin/floor, PID/start ticks, UID/GID, previous
boot, release mismatch, duplicate/malformed session fields,
symlinks, writable trust files, modified installed executable,
process exit and mid-inspection manifest replacement. Existing
B2B9/B2B10/B2B11, kernel identity and QML barrier regressions run
again. The review diff is restricted to five Clock files.

There is **no test of an installed root-owned production session
controller on Silverblue** and no claim that it currently exists.
