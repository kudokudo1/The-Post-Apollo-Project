## 3. Candidate proof-obligation chain (not packet fields)

These names are conceptual **review labels**, not a frozen network schema or API:

1. **S0 / SOURCE_AND_SELECTION:** Independently accepted native process/release and original compositor-selected mapped XDG lifetime. Bind original seat/session and lock, output/workspace identity, output origin/scale/transform, real object generation, compositor boot/source epoch and an operation-specific challenge. Need real operator-origin selection and a fresh actual transaction instruction source, not only #178's map-minted diagnostic transaction counter.
2. **H0 / HUMAN_REVIEWED_INTENT:** Actual trusted review surface and affirmative human gesture must cover the *same* selected S0 object; immutable checkpoint/window, current before rectangle, saved target rectangle, exact action order, output/workspace/scale, purpose and deadline. Display decimals are for people; protection must bind exact canonical bytes and prevent one-ULP changes. The current DOC 5 #2237 string shadow is not a trusted UI.
3. **C0 / C5_PROTECTED_SPENT:** A distinct, independently enrolled TimeW C5 authority atomically checks the approved immutable S0+H0 claim, active grant status, revocation epoch and independently current history, then commits **exactly one SPENT**, with rollback-resistant sequence/head and durable terminal recovery lookup. This commitment occurs *before any* SwayPX resize or move effect. Local SQLite/guest backups are never its current authority.
4. **R1 / NATIVE_RESIZE_OUTCOME:** Native producer binds **one original operation** and per-instruction fresh identity to a real selected object with post-resize actual logical geometry (which may include changed x/y). Distinguish queued/ready/timeout/copied-current/scene/presentation and verification gaps; a claimed ready serial does not alone prove final settlement. A forced timeout taints the operation. An independently accepted source/receipt criterion is needed before a later move; that criterion remains UNSPECIFIED and not executable.
5. **R2 / NATIVE_MOVE_OUTCOME:** Only after a jointly accepted **authenticated and settled R1** for the same object/seat/output/generation, one preauthorized continuation may request the reviewed move using *observed* actual post-resize geometry. It consumes **no new human grant** and cannot be dispatched from `CURRENT`, synthetic `PRESENT`, or an ACK-less `TIMEOUT`. The native producer must report its own separately authenticated move outcome/settlement evidence.
6. **T0 / TERMINAL_RECONCILIATION:** The protected authority and TimeW journal reconcile independently authenticated C0/R1/R2 terminal records from the **same** operation, key epochs, original selection and transaction lineage. A locally displayed `COMPLETE` is not an outcome authority. Record irreversible spending even when the operation failed or its final state is uncertain. Never infer rollback or consent refund from timeout.

**No step after R1 may proceed just because `CURRENT` equals the target**. SwayPX #176 proves this positive-looking state exists after a real timeout without a successful client ACK. SwayPX #178's process-local lifetime numbers reduce some ABA confusion but are not independently trusted source identities.

## 4. Mandatory binding and serialization *questions*

Before anyone writes a production packet, C5 requests written owner dispositions to each item. A blank or inconsistent answer is **REVISE/HOLD**, not an opportunity to invent a default.

- **Subject and authority:** Exact TimeW-only operation/audience/domain/version; immutable grant and operation IDs; consent issuer enrollment role/key epoch; **separate** native source receipt signer role; independent protected current-head/revocation/one-use SPENT authority; who verifies which key without trust-on-first-use.
- **Native original selection:** Which compositor event genuinely represents operator-selected window and gesture, with an authenticated unlocked seat/session? How is SwayPX #178's diagnostic boot/random tag transformed into producer-authenticated source evidence rather than accepting a self-generated input? Which actual `transaction_commit` per-instruction generation identifies R1/R2, independent of map time?
- **Lifetime:** Reuse-proof selected object, compositor boot, mapped XDG root, unmap, restart, original seat, locked/unlocked epoch, output/workspace attachment, scale/transform and origin. Which transitions invalidate C0/R1/R2? Never allow a reused pointer/serial or newly mapped same `app_id` to inherit consent.
- **Exact geometry:** Canonical version, coordinate space, origin, field order, byte order, bit representation, finite value bounds and phase semantics for before CURRENT, target intent, observed post-resize CURRENT and independently settled final. TimeW #2207's in-process `ExactLogicalRect` is **not** that approved cross-process wire; output dimensions are not automatically transformed logical available area. Preserve fractional 92.5 and one-ULP distinctions; no silent integer rounding.
- **Native settlement:** Define authenticated client-ready vs timeout, actual per-view scene/presentation and genuinely final settlement, including the case where moves need no configure. A synthetic `PRESENT_REPORTED` and `CURRENT` alone MUST fail.
- **Commit and transport:** Who chooses nonces, signs request/receipt domains, enforces total monotonic deadlines, atomically consumes a grant and advances current head, and exposes read-only idempotent outcome lookup? A retryable **lookup** is not a retryable **command**.
- **Revoke and recovery:** Define whether revocation occurs before or after C0, what SPENT means after denial or source failure, immutable terminal receipt retention, backup restore/fork detection, ACK loss, network split and authority outage. Never fall back to a local diagnostic ledger or reuse a grant/command nonce.
- **Rollout:** Who independently verifies actual installed SwayPX source release/process and protected transport; who owns key rotation and revocation; how is cutover from disposable local development to independent NAS/another Post-Apollo computer performed with **fresh enrollment/genesis** rather than promoting fixture state?

## 8. Original-effect fence continuity across custody and source epochs (proposed 2026-11-24)

**DOC 5 disposition to DOC 1 [#2581](https://github.com/kudokudo1/The-Post-Apollo-Project/pull/2581), source `13fc31491492abb86e15903a1c5f074785085ae1`: ACCEPT custody/effect separation and original-fence continuity as required semantics; REVISE TimeW-specific partial-effect/no-effect and affected-scope rules below; HOLD real wire, recovery service, signer enrollment and native execution.** This is an owner proposal for joint acceptance, not new production policy.

### Separate the three lifetimes

- **Original historical operation:** immutable TimeW purpose, original grant and operation, checkpoint, exact before/target binary64, selected XDG lifetime and original seat/source epochs, plus original instruction binding for each potentially effective resize/move. Retain enough authoritative correlation before any corresponding effect can be submitted. An independently current history must retain the original SPENT/fence even when the original actor or grant is no longer usable. A later lookup ID, process start or issuer epoch is never a replacement execution identity.
- **Current admission:** expiry, revocation, source restart/unmap/remap, seat/lock changes, key rotation or custody restore can invalidate permission to submit a new effect or continue R2. They do not prove the earlier R1/R2 did not happen. Do not transplant consent to a similar window, silently renew it or discard the original unresolved fence when an old key is retired.
- **Current read-only recovery:** a separately and presently authorized, purpose-bounded lookup may resolve the original historical operation after its admission expires. Authenticate current reader permission and independent history currency separately from historical issuer/source identity and key validity at the time of the recorded event. An old signature alone, or a current key signing a caller-supplied old record, proves neither. Rotation/recovery must preserve independently verified historical key/status/lineage and original-effect fences; if that continuity is absent, hold rather than reinterpret the old evidence. No chosen retention interval, query protocol or root is implied.

### TimeW-specific effect dispositions

These are candidate review outcomes, not executable state names or new positive return values. An independently current C5 SPENT is irreversible even when no window movement occurred.

| C5 history and effect-owner evidence | Proposed recovery treatment |
| --- | --- |
| Custody/current-history unavailable, stale, rolled back, forked or incomplete | UNKNOWN/HOLD; no terminal conclusion even with an apparently valid old native receipt |
| Original consent spent; R1 or R2 receipt absent, conflicting, partial, timed out or unverifiable | UNKNOWN/HOLD; preserve original spent state and affected-scope fence; no replay, undo, refund or fresh grant to bypass |
| Authenticated R1 settled but R2 absent/unknown | Record only the supported partial effect in reconciliation; whole operation is not no-effect or complete. Uncertain recovery never triggers a move. Ordinary same-grant continuation in the original active execution path still requires the jointly accepted R1 settlement and current live checks in section 3; a lookup is not that path. |
| Authenticated original no-effect for R1 and R2, with durable effect-owner proof that delayed, queued or duplicate submission of either step is impossible | Candidate terminal no-effect for this original operation only; retain any historical SPENT. No automatic grant refund, retry or release of a fence for a new overlapping operation. If one step did occur, no-effect of the other is only a partial outcome, not whole-operation no-effect. |
| Independently current original C5 spend and authentic selected-view R1/R2 terminal settlement agree with exact original lineage | Candidate settled original effect; never re-execute. Actual terminal policy, producer evidence and consumer implementation still require joint review. |
| Original identity or evidence lost beyond recovery | UNKNOWN/HOLD for the affected operation scope pending independently reviewed resolution. A new UUID, restored desktop layout or remapped same app ID cannot erase uncertainty. |

A missing row, output PRESENT, stable surface sequence, same client-buffer wrapper at one sample, timeout, canceled lookup or process exit is **not** proof of no effect and no delayed submission. [SwayPX #210](https://github.com/kudokudo1/Post-Apollo-SwayPx/pull/210) describes a diagnostic live wrapper-object comparison, not the effect-owner's durable terminal fence or final selected-frame receipt. The effect owner must account for already queued/in-flight instructions before a proposed no-effect disposition; preventing future calls only is insufficient.
