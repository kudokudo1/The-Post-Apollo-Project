## D2b — coordinated collector transport

Explicit one-shot Python runner launches 2–4 existing collectors concurrently through fixed argv, independently validates the workflow and refuses unlisted fields/targets. One newest same-user Quickshell PID/start-tick pin is resolved before spawning memory/thread collectors; the internal paired identity arguments are verified by each collector and not accepted in user workflow plans. Existing standalone and fixed QML captures remain unchanged. Each configured collector adds Linux monotonic timestamps, and the combined transport records actual overlap rather than claiming simultaneous first samples. Child streams are drained concurrently, 64KiB per child and 300000 bytes for the final ASCII JSON envelope. Cancellation/deadline only stop owned subprocesses, never the observed process. The runner reports COLLECTED (transport evidence only), NOT VERIFIED or CANCELLED, retaining individually collected successful results when another fails. Incomplete child data is not retained. No daemon, UI mount, archive writes, arbitrary command or protected action. Full metric evidence validation, session single-flight with existing owner, archive capacity/lifecycle and UI success are D2c gates. Outer timeout 145s, inner duration+20s; abrupt SIGKILL is not a graceful cancellation witness. Tests exercise disposable parallel barrier, cancellation/reaping, overflow, receipt mismatch and actual same-user census/storage in CI. Memory+thread common identity tests are synthetic; no desktop qualification. Depends on #2882 exact 69ee9616, merge dependency chain and recheck before integration.
