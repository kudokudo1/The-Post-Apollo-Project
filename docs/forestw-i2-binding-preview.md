# ForestW // I2 binding reference integration

**Patient:** The-Post-Apollo-Project · **Room:** ForestW UI · **Role:** external ForestW DOC · **Production:** HOLD

## IMPLEMENTATION
The existing AUTO PREVIEW EVALUATE action now calls a bounded helper which uses the same I1 recommendation builder and actual Core I2 resolve_reference/public_binding_status functions. The preview offers nine fictional binding evidence scenarios: unbound, missing evidence, changed artifact digest, not installed, install unknown, capability unknown, required feature unsupported, context insufficient, and reference match. Fixed fixture requirements are chat + reasoning, context 4096, output 256. Neither the selected Tree nor installed model names nor saved equipment supply the fixture identity. I2 consumes the actual I1 recommendation, and missing Big never substitutes Small. The parser checks exact echoed inputs, matching I1/I2 form, known reason, reference match consistency, null resolved binding/form and false authority flags. One existing helper process; complete successful stdout/stderr/exit required. Edits and closing reset results.

## HOW TO USE
Forest → flower → AUTO PREVIEW. Choose example form, reasoning and semantic evidence, then a fictional I2 scenario and EVALUATE. The UI reports the I1 recommendation, local equipment hint separately, I2 reason, and LIVE BINDING // UNRESOLVED.

## VERIFY
Existing I1 tests retain 432 example combinations. New test_forest_binding_preview_i2.py covers nine I2 outcomes across four I1 form paths (36 cases), malformed helper arguments, actual joined receipt and negative UI parser/source tests. Native acceptance separate.

## WATCH OUT FOR
Reference match is not compatibility proof for the installed model. No real artifact digest, runtime identity, capability measurements, context configuration, resource fit, permission, model binding, tool action or inference. I2 merged but independent review was not recorded at reconciliation. Fixed hypothetical examples are deliberately not a live model profile. The new scenario section increases preview content height; native scrolling and usability are pending.

## NEXT / DECISIONS
Independent review, operator acceptance. Actual model capability profile requires reviewed evidence producers. Do not promote local preferences or B0/P0 model names to trusted bindings. Next prefer consuming current Core measurement/context contracts or live non-private evidence when available rather than adding further hypothetical controls. Production HOLD.
