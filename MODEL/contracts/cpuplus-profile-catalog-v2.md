# CPU++ PROF M4e catalog v2 — preview data only

V1 requests and files remain unchanged. A v2 request adds exactly `schema: "post-apollo-cpuplus-profiles-v2"`. V2 list projects V1 rows with all new fields null, without changing the file or revision. Only an explicit revision-checked v2 create/edit/rename/delete commits v2. Once committed, v1 readers and writers refuse; there is no silent downgrade. Do not enable v2 UI writes until the matching UI is reviewed.

Each v2 target object has exactly capacityGiB, swappiness, zram, priority, advanced. Null means unset, never default or permission. Zram is {deviceHint,sizeKiB,algorithm}; priority is {deviceHint,sizeKiB,value}. Device paths are descriptive hints; size is observed capacity, not identity. No stored source identifier, protected permission or application behavior. Future preview must independently reobserve the selected device and supported algorithms. Priority is explicit nonnegative 0..32767. Advanced has exactly cachePressure, background, writer, writebackCentisecs, expireCentisecs, each independently nullable. Background/writer carry {unit,value}, unit % or B; values positive in the observed unit. Zero or inconsistent observed pairs cannot become a target. Integer bounds mirror current preview, not kernel apply validation. No automatic threshold ordering or conversion; mixed units require a fresh comparison and may be incomparable. The existing capacity and swappiness bounds remain. Presets remain unset. Process protections, automation, notifications, rollback and application are intentionally outside this schema. No new process or writes on startup.

The same private catalog file, lock and revision are used. No secondary catalog or daemon. Same-UID cooperative storage is not a trust boundary. Provisional format requires independent review before UI integration.
